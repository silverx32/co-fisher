# Co-Fisher 摸鱼搭子 —— 方案 / 可行性审查 / 开发计划

## 一、方案

| 模块 | 设计 |
| --- | --- |
| 形态 | Windows 桌面宠物：透明、无边框、置顶的小窗，默认停在屏幕右下角（任务栏上方），可拖动；托盘图标可显示/隐藏/退出 |
| 角色 | 8 个原创 Q 版"AI 拟人"小人，每个有 **待机图 idle.svg** 和 **敲键盘图 typing.svg**（SVG 内含呼吸、眨眼、敲键动画）；支持自定义皮肤：放两张 PNG/GIF 即可，并会同步给好友 |
| 计数 | 全局键盘钩子（uiohook-napi）只统计**按下次数**，不记录按了什么键；长按不重复计数；点数本地持久化 |
| 道具 | 番茄 50 点、墨鱼汁 100 点、💩 200 点；兑换后点数立刻扣减，道具进背包 |
| 糊脸 | 被扔的好友屏幕上弹出一个全屏透明、鼠标可穿透的覆盖层：道具飞入 → 啪地糊在屏幕上 → 滴落/苍蝇 → 约 6 秒淡出，并提示"XX 扔了你一脸番茄" |
| 联机 | 房主的 App 内置 WebSocket 服务器（默认端口 23333，可设房间密码），最多 8 人；所有人（包括房主自己）都作为客户端连进来，同一套代码路径 |
| 好友状态 | 宠物上方显示好友卡片：好友当前小人（实时切换 idle/typing 图）、名字、点数；点击卡片选道具扔过去 |

### 数据流

```
键盘钩子 ─▶ 主进程(钱包:点数/背包, 持久化) ─▶ 宠物窗口(自己的小人/气泡)
                    │  每 150ms 上报 {点数, 是否在敲, 背包}
                    ▼
            WebSocket 客户端 ◀──────▶ 房主的 WebSocket 服务器(名单+转发)
                    │ 收到 hit
                    ▼
             覆盖层窗口(糊脸特效)
```

* 钱包（点数/背包）以**本地为准**：离线也能攒点数、兑换道具；扔道具需要在线，服务器确认后才扣背包。
  朋友间小游戏，不做反作弊，只在服务器做基础限流（每秒按键上限、扔道具频率、消息体大小）。

## 二、可行性审查

| 风险点 | 结论 / 对策 |
| --- | --- |
| 全局键盘监听 | `uiohook-napi` 是 N-API 原生模块，自带 win32-x64 预编译，Electron 可直接加载，无需编译环境 ✅。少数杀软可能提示"键盘钩子"——只计数不记录内容，在 README 说明 |
| 透明置顶+点击穿透 | Electron `transparent + alwaysOnTop + setIgnoreMouseEvents(true,{forward:true})`，鼠标移到小人/卡片上时才接收点击 ✅ |
| 糊脸覆盖层不抢焦点 | 覆盖层 `focusable:false` + `showInactive()` + 全程鼠标穿透，用户正在打字不会被打断 ✅ |
| 房主当服务器 | 局域网直接用；跨网需端口映射或 Tailscale / ZeroTier / 蒲公英等虚拟局域网 ⚠️（README 写明）。Windows 首次监听端口会弹防火墙提示，需要允许 |
| 8 人负载 | 每人每 150ms 一个很小的 JSON 包，服务器 100ms 合并广播，负载可忽略 ✅ |
| 角色版权 | 网上流行的 AI 娘化形象（DeepSeek 鲸鱼娘、Claude 橘发姐姐等）出自 B 站画师 ZipZipPipe 等人的同人作品，**有著作权，不能直接打包分发** ⚠️。对策：参照其流行"人设梗"（鲸鱼兜帽、橘发眼镜、柴犬耳、彩虹发……）**原创绘制** SVG 小人；并提供自定义皮肤功能，用户可放入自己有权使用的图片 |
| 打包 | `@electron/packager` 输出免安装文件夹 + zip，原生模块解包到 asar 外 ✅ |

## 三、开发计划

1. 工程骨架：Electron + ws + uiohook-napi，目录 `src/main`（主进程）、`src/renderer`（界面）、`src/shared`（协议/道具）
2. 角色生成器 `tools/gen-characters.js`：参数化画 Q 版小人，输出 8×2 张 SVG 到 `assets/characters/`
3. 服务器 `src/main/server.js`：握手/密码/人数上限/名单/限流/心跳/转发
4. 客户端 `src/main/net-client.js`：自动重连、批量上报
5. 主进程 `main.js`：窗口、托盘、键盘钩子、钱包持久化、IPC
6. 宠物窗口 UI：小人、气泡计数、好友卡片、面板（房间 / 角色 / 商店）
7. 覆盖层：三种道具的糊脸特效
8. 单元测试（服务器协议）+ 代码 Review + 修复
9. 打包成品 + README

## 四、v2 调整（2026-10-30）

| 项目 | v1 | v2 |
| --- | --- | --- |
| 技术栈 | Electron（成品 140MB） | Tauri 2 + Rust，界面用系统自带 WebView2（exe 约 8MB，其中角色图约 5MB） |
| 角色 | 8 个 SVG 原创小人 | 6 个 PNG 角色（Claude、Codex、豆包、Gemini、DeepSeek、Kimi），1 待机 + 3 打字帧，每次按键随机闪一帧后回到待机（图集由 `tools/slice-atlas.js` 切分） |
| 扔道具 | 点好友 → 弹出菜单选道具 | 好友小人下面常驻 3 个道具按钮，显示自己的存货，0 时禁用，点一下直接扔 |
| 跨网联机 | 端口映射 / 虚拟局域网 | 新增独立中转服务器 `cofisher-relay`（多房间、房间号隔离，Linux 静态单文件 <1MB）；房主模式支持 IPv6 直连 |
| 其他 | — | 自动重连上次的房间；房主/中转共用同一套服务器代码 |

**跨网方案对比**：中转服务器最稳（需要一台云服务器，推荐 Ubuntu 22.04/24.04 LTS，1 核 1G 足够）；IPv6 直连免费，但取决于双方宽带是否有公网 IPv6、光猫是否放行入站；不需要服务器的 P2P 打洞（NAT 穿透）在对称型 NAT / 运营商级 NAT 下成功率低，且仍需要一个信令服务器，所以没有采用。

## 八、v2.4 调整

| 项目 | 内容 |
| --- | --- |
| 房间 Boss | 服务器为每个房间维护一只 Boss（8 种轮流出现，各有强度系数）：血量 = 每人 1500 × 这一场同时在线的最多人数（最多 16）× 强度：同时在线人数创新高才加血，同一个人进进出出、换新 id 进来都不会叠加。伤害来自服务器已经按打字速度限速过的点数增长（status 里 count 的增量），花点数不算；state 里带 `boss`（emoji / name / level / hp / max / in / minPct），玩家条目带本轮伤害 `dmg` |
| 打败 | 扣到 0 时广播 `bossDown`（killer；rewarded = 当时在房间里、伤害占总血量 3% 以上的人；另带每人伤害 damage、total、minPct），进入冷却（默认 20 分钟），冷却结束且房间里有人时刷出下一只；中转可用 `--boss-hp`、`--boss-cooldown` 调整 |
| Boss 宝箱 | 客户端收到 `bossDown` 后自己记一个 Boss 宝箱（存档 `bossChests`；补刀的人记 `luckyChests`，稀有度权重 540/290/120/40/10 ‰，普通宝箱是 620/260/90/25/5）。小人下面的气泡和装扮页可以打开，不花点数、没有冷却 |
| 宝箱道具 | 所有宝箱 25% 开出道具：先按稀有度抽，再在该稀有度的道具包里随机一个（普通 🍅×10 等，神话 🌧️×6 + 🎆×6 + ☂️×2） |
| 雨伞涨价 | 150 → 500 点：比任何单体道具都贵、是番茄雨的一半，挡下一次攻击不再稳赚，也不容易囤成"免疫"；道具包里的雨伞数量相应减少 |
| 界面 | Boss 卡片在好友上方：血条、伤害飘字、自己的伤害占比（不到 3% 显示红色）、悬停看伤害排行；打败时显示最后一击并放一场烟花（免打扰时不弹全屏），冷却时显示下一只和倒计时 |

## 九、v2.5 调整

| 项目 | 内容 |
| --- | --- |
| 鼠标点击 | `app/src/keyboard.rs` 改名 `input.rs`，在键盘钩子旁边加了低级鼠标钩子 `WH_MOUSE_LL`（各自一个线程和消息循环，一个装不上另一个照常计数）：左 / 右 / 中 / 侧键每按下一次算一次，移动和滚轮不算。点击和按键共用同一个计数，所以同样攒点数、闪打字图、算"在打字"、打 Boss；服务器的每秒 40 次上限不变。回调对每次鼠标移动都会被调用，所以只比较消息类型、做一次原子加法就返回 |
| 每日统计 | 存档新增 `daily`（本机日期 "YYYY-MM-DD" → 当天按键 + 点击次数，用 `GetLocalTime` 按本机时区在零点分日）和 `dailyLastHits`（当天补了几次 Boss 最后一刀，没有就不记）。`local` 事件带上当天的新值 `daily`，只存在本机、不上传 |
| 日历 | 面板新增「日历」页（点小人下面的点数气泡也能打开）：今日累计和评价、最后一击（今天 / 累计）、周一开头的月历，可以往前翻到第一天有记录的月份。每天按次数分档上色并给评价：休息（有记录以来某天一次都没有）/ 摸鱼 1+ / 搬砖 3000+ / 勤奋 1万+ / 爆肝 2万+ / 卷王 4万+；五档颜色是同一个蓝色由浅到深（按顺序色阶检查过：亮度单调、相邻档拉得开、最浅一档在白底上也有 2:1），格子里另有表情，颜色不是唯一的区分 |
| Boss | 8 → 16 种，新增卡纸打印机、夺命连环 Call、报销单妖、已读不回幽灵、画饼大师、祖传代码恐龙、线上事故、996 魔王，和原来的按强度穿插排列（80% → 160%）。`BOSSES` 改成带 `id` 的结构体并公开给客户端；state 的 `boss` 和 `bossDown` 新增 `id`，v2.4 的服务器不发 id，客户端按名字对应原来那 8 只 |
| Boss 专属装扮 | 每只 Boss 5 件（每种稀有度 1 件，共 80 件，decos.json 里带 `boss`）。补最后一刀且伤害达到 3% 时，客户端除了幸运宝箱，再按 `BOSS_DROP_WEIGHTS`（普通 45 / 稀有 30 / 史诗 16 / 传说 7 / 神话 2 %，某只 Boss 缺的稀有度不参与）从这只 Boss 的专属装扮里抽一件。专属装扮不进宝箱，合成也合不出来，但可以当合成材料；在「装扮 → ⚔️ Boss」里按 Boss 分组显示掉落率，Boss 卡片的悬停提示也会列出它会掉什么 |
| 合成 | 改成自己挑：点「挑材料合成」后点装扮加一份（第一份决定稀有度，其他稀有度变灰），`merge_decos` 收到 { id: 份数 }，要正好 10 份、同一稀有度、都拥有，正在穿的留一件，用到某件的最后一份要再点确认。「补满」（`fill_merge`）照原来自动合成的顺序补：先重复的（普通装扮先于 Boss 专属、份数多的先），再普通装扮只有一件的；只有一件的 Boss 专属只能手动挑。结果仍是下一稀有度的普通装扮里随机一件 |
